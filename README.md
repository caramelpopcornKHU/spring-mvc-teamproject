
## REST API 성능 비교 분석: Spring Boot vs. NODE.JS

### 1. 개요 및 최종 결론

본 보고서는 Spring Boot 기반 REST API와 JS 기반 REST API를 대상으로 진행한 스트레스 테스트(Stress Test) 및 스파이크 테스트(Spike Test) 결과를 비교 분석합니다. 테스트는 k6 툴을 사용하여 진행되었습니다.

**최종 결론:**

두 API의 성능 테스트 결과만을 놓고 볼 때, **Spring Boot API가 압도적인 안정성과 견고함을 입증했습니다**. Spring Boot는 어떠한 부하 상황에서도 100%의 성공률을 기록하여 서비스의 신뢰성이 검증되었지만, JS API는 부하가 증가하거나 순간적인 트래픽 급증 시 심각한 불안정성을 노출했습니다. **서비스의 신뢰성이 최우선이라면 Spring Boot가 현재로서는 더 나은 선택입니다**.

---

### 2. 상세 비교 분석 결과

#### 2.1. 스트레스 테스트 (Stress Test) 결과

지속적인 고부하 환경을 시뮬레이션한 스트레스 테스트 결과입니다. Spring Boot는 모든 요청을 성공적으로 처리한 반면, JS는 요청 실패를 기록했습니다.

| 항목 (Metric) | Spring Boot REST API (✅ 안정적) | JS REST API (❌ 불안정) | 해석 |
| :--- | :--- | :--- | :--- |
| **성공률** | **100%** (36,614개 요청 모두 성공) | **98.03%** (760개 실패) | Spring Boot는 모든 부하를 안정적으로 처리했으며, JS는 약 2%의 요청이 실패했습니다. |
| **처리량 (RPS)** | 303 req/s | **320 req/s** | JS가 초당 약 17개 더 많은 요청을 처리했습니다. 처리량 자체는 JS가 약간 높습니다. |
| **평균 응답 시간** | 3.22s | **2.98s** | JS의 평균 응답 시간이 약 0.24초 더 빨랐습니다. |
| **상위 95% 응답 시간 (p95)** | **6.78s** | 7.51s | JS는 느린 요청(상위 5%)이 Spring Boot보다 더 느려 특정 상황에서 성능 저하가 심해짐을 나타냅니다. |
| **네트워크 사용량 (수신)** | 9.8MB | 39MB | JS API가 더 많은 데이터를 주고받았습니다. |

> *참고: 스트레스 테스트의 통계적 유의성 검정(Welch Two Sample t-test) 결과 p-value는 0.05831로, 95% 신뢰 수준에서는 평균 응답 시간 차이가 통계적으로 유의미하다고 보기 어렵습니다*.

#### 2.2. 스파이크 테스트 (Spike Test) 결과

순간적인 트래픽 급증 상황을 시뮬레이션한 스파이크 테스트 결과입니다. 이 테스트에서 JS API는 심각한 불안정성을 노출했습니다.

| 항목 (Metric) | Spring Boot (✅ 압도적 안정성) | JS (❌ 심각한 불안정성) | 해석 |
| :--- | :--- | :--- | :--- |
| **성공/실패율** | **100% 성공** / 0% 실패 | 95.75% 성공 / **4.24% 실패** | JS의 실패율이 스트레스 테스트보다 **2배 이상 증가**하여, 순간적인 부하에 매우 취약함을 보여줍니다. |
| **상위 95% 응답 시간 (p95)** | **7.47s** | **15.75s** | JS는 사용자의 5%가 **15초 이상** 기다려야 했으며, 이는 시스템이 **서비스 불능 상태에 가까워졌음**을 의미합니다. Spring Boot는 7.5초 내로 응답 시간을 제어했습니다. |
| **최대 응답 시간 (max)** | **7.98s** | **22.94s** | JS API는 최악의 경우 23초에 가까운 응답 시간을 기록했습니다. |

> *참고: 스파이크 테스트의 Welch Two Sample t-test 결과 p-value는 0.01753으로, 95% 신뢰 수준에서 두 시스템의 평균 응답 시간 차이가 통계적으로 **유의미함**을 나타냅니다*.
